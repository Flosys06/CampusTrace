## 1. Executive Summary

During this maintenance and UX refinement session, **CampusTrace** underwent a comprehensive codebase audit, architectural stabilization, and mobile-first experience optimization. 

Key milestones achieved:
- **Zero Data Loss**: Existing SQLite records in `backend/campustrace.db` (14 multi-tenant VTU users, 68 colleges, 7 item reports, 6 matches, 3 claims) were strictly preserved without resetting or dropping tables.
- **Notification Link Rectification**: Repaired hardcoded broken routes (`/teacher/claims/:id` and `/teacher/reports/:id`) in backend services (`claims.py`, `custody.py`, `matching_engine.py`) to align with registered frontend routes (`/claims` and `/reports/{id}`). Added backward-compatibility client redirects in `App.tsx` so historical database records continue to resolve seamlessly.
- **Physical Return Workflow Connected**: Enabled query-based claim filtering on `GET /api/claims?report_id={id}` and replaced manual numeric claim ID typing on `ReportDetailPage.tsx` with a dynamic `<select>` dropdown pre-filling from `ClaimsPage` navigation.
- **Pydantic V2 & Python 3.14 Modernization**: Modernized all 6 backend schema files to `model_config = ConfigDict(from_attributes=True)` and replaced deprecated `datetime.utcnow()` with `datetime.now(timezone.utc)`.
- **Duplicate Action Removal**: Replaced competing standalone report links in `ListingsPage.tsx` with unified `openReportFlow` triggers, and purged dead legacy layout components (`Navbar.tsx` and `Sidebar.tsx`).
- **Mobile-First UX & Viewport Polish**: Added viewport constraints (`max-h-[90vh] overflow-y-auto`) to all modal dialogs (claims, custody handover, return verification, profile edit) preventing cutoffs on mobile keyboards. Added horizontal scrolling to segmented buttons and snap-scrolling to home carousels.
- **Camera-to-Report Desktop & Mobile Refinements**: Added desktop drag-and-drop support to `CameraReportFlow.tsx` with visual drop zone feedback, MobileNetV2 AI vision prefill, and double-click submission protection.
- **Role-Aware Home Screen**: Customized `HomeScreen.tsx` to display targeted hubs: Faculty Custody & Review Hub for Teachers, Institutional Oversight Hub for Admins, and AI Camera Vision entry point for Students.

## 4. Phase 2: AI Detection Improvements, Report Closure & Official Branding (October 16, 2026)

### A. AI Image Detection & Matching Engine Overhaul
1. **Letterbox Border Contamination Fix (`vision_extractor.py`)**:
   - Previous behavior: Applied CLAHE equalization, color histograms, and Sobel gradient filters across the entire 224x224 padded canvas including neutral gray `128` border bars. This injected identical ~90% color and gradient correlations between arbitrary objects.
   - Solution: Preprocessed image content directly with CLAHE *before* letterboxing; computed global 128-dim color histograms, dominant colors, spatial 2x2 grid pyramids, and Sobel gradient orientations strictly over valid image content. Neutral canvas padding is now isolated solely to the CNN input tensor.
2. **Proper Calibrated Cosine Similarity (`vision_extractor.py`)**:
   - Introduced calibrated visual confidence mapping: baseline raw cosine floor of 0.45 maps to zero confidence; 0.45–0.70 maps to 0.0–0.55; >= 0.70 ramps smoothly to 1.0. Unrelated objects drop to < 0.15, while true matches score 0.75–0.99.
3. **Text Token Similarity & Brand Conflict Penalty (`matching_engine.py`)**:
   - Added `_extract_tokens` and `_compute_text_and_brand_score`:
     - Tokenized titles with stop-word removal and Jaccard overlap.
     - Brand consistency checks: Matching brands boost text score; conflicting explicit brands (e.g., Apple vs. Titan) enforce a heavy penalty (capped at 0.10).
     - Gated unphotographed items: Disjoint item titles with zero shared tokens (e.g., "Silver MacBook Pro 14" vs "Titan Chronograph Watch") cannot exceed 0.40, completely preventing false-positive metadata matches.
4. **Visual Gating (`matching_engine.py`)**:
   - When both reports include photographs, if calibrated visual similarity is low (< 0.25), composite score is hard-clamped to `<= 0.35`. Metadata is prohibited from manufacturing matches between visually dissimilar items.
5. **Exclusion of Closed & Returned Reports**:
   - Filtered out `ReportStatus.CLOSED` and `ReportStatus.RETURNED` from candidate discovery in `matching_engine.py`, report match queries in `reports.py`, and global match queries in `matches.py`.
   - Results are sorted in descending order of similarity score.

### B. Report Closure Workflow
1. **Database & Model Integration (`report.py` & `schemas/report.py`)**:
   - Mapped `resolution_type` and `resolution_notes` columns in SQLite `reports` table to SQLAlchemy `Report` model and Pydantic `ReportResponse`.
   - Added `ReportCloseRequest` schema.
2. **Endpoints (`backend/app/api/reports.py`)**:
   - Added `POST /api/reports/{id}/close`:
     - Authorization: Owner student or campus teacher/admin within institution scope. Non-owners receive 403 Forbidden.
     - Enforces state invariants: Cannot close already `CLOSED` or `RETURNED` reports.
     - Sets `status = CLOSED`, `resolved_at = datetime.now(timezone.utc)`, `resolution_type`, and `resolution_notes`.
     - Logs audit event `REPORT_CLOSED`.
   - Added `POST /api/reports/{id}/reopen`:
     - Restores report to `OPEN` (or `IN_CUSTODY` if physical custody records exist).
     - Clears resolution fields and logs audit event `REPORT_REOPENED`.
   - Claims prohibited on closed items in `claims.py` (400 Bad Request).
3. **Frontend Implementation**:
   - Added `closeReport` and `reopenReport` to `frontend/src/services/api.ts`.
   - Added `CLOSED` badge styling (neutral slate) in `StatusBadge.tsx`.
   - In `ReportDetailPage.tsx`:
     - Contextual "Close Report" button for owner or staff.
     - Contextual "Reopen Report" button for closed reports.
     - Confirmation modal with required text: *"Close this report? This report will no longer appear in active lost and found searches or generate new match suggestions. You can still view its history."*
     - Reason dropdown (`No longer needed`, `Item found elsewhere`, `Duplicate report`, `Other`) and optional notes input.
     - Prominent closure notice banner displaying date, reason, and notes.
     - Hid "Claim This Item" and return verification on closed reports.
     - Added `CLOSED` filter option in `ListingsPage.tsx`.
